# golova

Личный дневник головной боли с Google Таблицей в качестве хранилища. Работает по `/golova` на собственном сервере. Существующие команды Siri, iPhone и Apple Watch продолжают писать через Apps Script; сайт читает и пишет напрямую через Google Sheets API.

## Возможности

- Статистика за 30/90/365 дней, всё время или выбранные даты.
- Частота приступов, сила боли, средняя длительность, дни начала боли и число приёмов таблеток.
- Подробные карточки: начало, окончание, лекарства, заметки, хронология, погода, давление и его изменения, пульс, пульс в покое и HRV.
- Поиск по истории, фильтры силы и завершённости, раскрытие всех подробностей.
- Запись начала боли, окончания и приёма таблетки с сайта.
- Автообновление раз в минуту, адаптация к телефону, вход по паролю.

## Устройство

`static/index.html` — интерфейс без сборки и внешних библиотек. `server.py` — HTTP API на Python 3.12, слушает только `127.0.0.1:8177`. Nginx обслуживает страницу и проксирует API. Для доступа к таблице используются официальный пакет `google-auth` и сервисный аккаунт.

В репозитории нет ключей Google, действующего пароля, конфигурации сервера и записей дневника. Скриншоты с личными данными также не включены.

## Подключение Google

1. Создайте проект Google Cloud и включите Google Sheets API.
2. Создайте сервисный аккаунт без ролей на ресурсы проекта, скачайте JSON-ключ.
3. В самой Google Таблице выдайте этому аккаунту роль **Редактор**. Общий доступ оставьте ограниченным.
4. Сохраните ключ на сервере в `/etc/golova/service-account.json`, владелец `root:golova`, права `640`. Каталог `/etc/golova`: `root:golova`, права `750`.

Google Sheets API не требует изменения или нового развертывания Apps Script. Стандартные запросы Sheets API бесплатны в рамках квот Google; сервер и домен оплачиваются отдельно.

## Запуск на Ubuntu

Создайте системного пользователя `golova` без интерактивного входа. Скопируйте проект в `/opt/golova`; исходники и виртуальное окружение должны быть доступны пользователю службы на чтение и выполнение.

```sh
sudo apt-get install python3-venv nginx
python3 -m venv /opt/golova/venv
/opt/golova/venv/bin/pip install -r /opt/golova/requirements.txt
```

Скопируйте `static/index.html` в `/var/www/golova/index.html`. Дайте Nginx доступ на чтение файла и проход по каталогу.

Скопируйте `deploy/environment.example` в `/etc/golova/environment` и задайте ID таблицы и разрешённые адреса сайта. Для файла окружения используйте `root:golova`, права `640`. Создайте пароль:

```sh
sudo python3 /opt/golova/deploy/set_password.py
```

Установите `deploy/golova.service` в `/etc/systemd/system/`. Добавьте блоки из `deploy/nginx.conf` в существующий HTTPS server block вашего домена. Затем:

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now golova
sudo nginx -t
sudo systemctl reload nginx
```

Для обновления только интерфейса достаточно заменить `/var/www/golova/index.html`. Для обновления Python-кода перезапустите `golova.service`. Перед изменениями сохраняйте резервные копии.

## Требования к таблице

Листы: `Головная боль` и `Таблетки`. Заголовки строки 1 должны совпадать с исходным журналом. Сайт останавливает запись нового приступа при несовпадении схемы, чтобы не сместить значения. Он не создаёт и не удаляет листы или существующие записи.

Время берётся из часового пояса таблицы. Дни с болью считаются по датам начала; продолжение через полночь отдельно не добавляется. Средняя длительность учитывает только корректно завершённые записи. Неизвестные значения не считаются нулём. Интервал от начала до таблетки показывается только когда его можно однозначно определить внутри завершённого приступа длительностью менее суток.

## API

- `GET /golova/api/status` — состояние подключения и сеанса, без медицинских данных.
- `POST /golova/api/login` — `{ "password": "..." }`.
- `POST /golova/api/logout` — `{}`.
- `GET /golova/api/data` — записи для авторизованного сеанса.
- `POST /golova/api/record` — действие `start`, `end` или `pill`.

Все POST-запросы требуют `Content-Type: application/json` и разрешённый `Origin`. Пароль хранится в виде PBKDF2-хеша. Сеансы используют cookie `Secure`, `HttpOnly`, `SameSite=Strict`, живут 8 часов и сбрасываются после перезапуска сервера. После 8 неудачных попыток вход ограничивается на 15 минут. Backend не пишет содержимое записей в журнал запросов.

Запись выполняется одним `batchUpdate`. При неопределённом результате сетевого запроса проверьте таблицу перед повтором, чтобы не создать дубль. Действия сайта сериализуются внутри процесса; существующий Apps Script выполняется независимо.

## Проверка

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests
```

Тесты проверяют даты и длительность, формат новых записей, безопасное сохранение текста, завершение приступа и привязку таблетки. К Google они не обращаются и реальные записи не создают.
